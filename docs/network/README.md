# شبکهٔ فروشگاه‌های زنجیره‌ای و طرف قرارداد

> شاخه: `retail-network` — تاریخ: ۱۸ آبان ۱۴۰۵ (2026-11-09) — مهاجرت: `0081_retail_network`

این بخش فهرست فروشگاه‌های زنجیره‌ای و صنفی (FMCG، آجیل و خشکبار، فرش، موکت، سنگ، لوازم خانگی و هر حوزهٔ دیگری که از پنل اضافه شود) را با شعبه‌هایشان در ۳۱ استان نگه می‌دارد و روی نقشه نشان می‌دهد.

## قاعدهٔ اصلی نمایش
یک شعبه فقط وقتی در سایت دیده می‌شود که هر سه شرط برقرار باشد:
1. وضعیت قرارداد **خود شعبه** `active` باشد؛
2. وضعیت قرارداد **زنجیره** `active` باشد؛
3. زنجیره دادهٔ واقعی باشد (`provenance = real`).

بقیه (`prospect` بالقوه، `negotiating` در مذاکره، `paused` متوقف، `ended` پایان‌یافته) فقط در پنل مدیر دیده می‌شوند. با متوقف کردن زنجیره، همهٔ شعبه‌هایش فوراً از سایت حذف می‌شوند.

فعال کردن زنجیره بدون **شمارهٔ قرارداد** یا **تاریخ امضا** ممکن نیست (`contract_evidence_required`).

## قاعدهٔ داده (AGENTS.md بند ۹)
- فهرست شعبه‌ها فقط از منبع واقعی وارد می‌شود. هر شعبه باید منبعش را داشته باشد:
  - `data_source`: یکی از `chain_file` (فایل خود زنجیره)، `contract` (پیوست قرارداد)، `chain_website` (سایت رسمی زنجیره) یا `field_visit` (بازدید میدانی)
  - `source_reference`: نام فایل، شمارهٔ قرارداد یا نشانی صفحه
- ساختن یا حدس زدن شعبه ممنوع است. هیچ زنجیره یا شعبه‌ای در مهاجرت وارد نشده است.
- فقط دو فهرست مرجع وارد شده است: ۳۱ استان (با مرکز استان) و شش حوزهٔ شروع.
- مختصات «مرکز استان» تقریبی است و فقط برای جای دایرهٔ پوشش روی نقشه است، نه مرز یا نشانی.
- جدول شهرها هنگام ورود شعبه پر می‌شود. کد رسمی شهر/شهرستان (`official_code`) فقط از فهرست رسمی پر شود.
- قرارداد گیفت‌آسان با زنجیره‌ها برای شصت آنلاین **کافی نیست**؛ قرارداد جدا لازم است.

## مدل داده
| جدول | کاربرد |
| --- | --- |
| `network_provinces` | ۳۱ استان: slug، نام، مرکز استان، مختصات تقریبی مرکز |
| `network_cities` | شهرها/شهرستان‌ها (یکتا در هر استان) |
| `chain_sectors` | حوزه‌ها؛ از پنل قابل افزودن و خاموش کردن |
| `retail_chains` | زنجیره: نام، برند، وبسایت، وضعیت و شماره/تاریخ قرارداد، مسئول، اتصال اختیاری به فروشندهٔ پلتفرم |
| `retail_chain_sectors` | حوزه‌های هر زنجیره |
| `chain_branches` | شعبه: کد شعبه (یکتا در زنجیره)، استان، شهر، محله، نشانی، مختصات، تلفن، وضعیت قرارداد، منبع داده، اتصال اختیاری به `supplier_locations` |

`supplier_locations` دست نخورده است. اتصال شعبه به محل فروشنده (`supplier_location_id`) برای مرحلهٔ بعد است: تحویل پک پرسنل از نزدیک‌ترین شعبه با کد دریافت موجود در `in_person_service`.

## API
**عمومی (بدون ورود):**
| مسیر | خروجی |
| --- | --- |
| `GET /api/v1/network?province=&sector=&chain=&city=` | شعبه‌های فعال |
| `GET /api/v1/network/coverage?sector=` | پوشش هر استان (تعداد شعبه، زنجیره و شهر) |
| `GET /api/v1/network/sectors` | حوزه‌های فعال |
| `GET /api/v1/network/chains?sector=` | زنجیره‌های طرف قرارداد |
| `GET /api/v1/network/chains/<slug>` | صفحهٔ زنجیره |
| `GET /api/v1/network/provinces/<slug>` | صفحهٔ استان با تفکیک شهر |

استان را می‌توان با slug (`isfahan`) یا نام فارسی (`اصفهان` یا `استان اصفهان`) فرستاد. «ي/ك» عربی خودکار به «ی/ک» تبدیل می‌شود.

فیلدهای مدیریتی (منبع داده، وضعیت قرارداد، کد شعبه) هرگز در خروجی عمومی نیست.

**مدیر (`role=admin`؛ همهٔ تغییرها در `audit_logs` ثبت می‌شود):**
- `GET/POST /api/v1/admin/network/chains`، `PUT /api/v1/admin/network/chains/<id>`
- `GET/POST /api/v1/admin/network/branches`، `PUT /api/v1/admin/network/branches/<id>`
- `GET/POST /api/v1/admin/network/sectors`، `PUT /api/v1/admin/network/sectors/<id>`
- `GET /api/v1/admin/network/branches/template.csv`: فایل نمونهٔ خالی
- `POST /api/v1/admin/network/branches/import`: ورود گروهی (توضیح پایین)

## ورود گروهی از CSV
ستون‌ها (UTF-8، سطر اول عنوان):

```
chain_slug,branch_code,title,province,city,district,address,latitude,longitude,phone,contract_status,data_source,source_reference
```

- الزامی: `chain_slug`، `branch_code`، `province`، `city`، `data_source`، `source_reference`
- زنجیره باید از قبل در پنل ساخته شده باشد.
- کلید یکتا `chain_slug + branch_code` است: ورود دوباره همان شعبه را به‌روز می‌کند و تکراری نمی‌سازد.
- مختصات باید داخل محدودهٔ ایران باشد؛ جابه‌جا بودن عرض و طول رد می‌شود. ارقام فارسی پذیرفته می‌شود.
- حداکثر ۵۰۰۰ ردیف و ۲ مگابایت.

روش کار:
1. بدون `?commit=1` بفرستید (اجرای آزمایشی). همه‌چیز واقعاً بررسی می‌شود ولی چیزی ذخیره نمی‌شود. خطای هر ردیف با شمارهٔ سطر برمی‌گردد.
2. خطاها را در فایل اصلاح کنید.
3. با `?commit=1` بفرستید. ردیف‌های سالم ذخیره می‌شوند و ردیف‌های خطادار هیچ اثری نمی‌گذارند.

کدهای خطای ردیف: `unknown_chain`، `unknown_province`، `missing_source`، `missing_field`، `invalid_coordinate`، `invalid_status`، `duplicate_row`، `branch_exists`.

## روش افزودن یک زنجیرهٔ تازه
1. در پنل، زنجیره را با وضعیت `prospect` یا `negotiating` و حوزه‌هایش بسازید.
2. فهرست شعبه‌ها را از خود زنجیره بگیرید و به قالب CSV دربیاورید. منبع را در `source_reference` بنویسید.
3. فایل را آزمایشی، سپس نهایی وارد کنید (شعبه‌ها هنوز در سایت دیده نمی‌شوند).
4. پس از امضای قرارداد، شماره یا تاریخ قرارداد را ثبت و زنجیره را `active` کنید.
5. شعبه‌هایی را که در قرارداد آمده‌اند `active` کنید (در CSV ستون `contract_status`).

## صفحه‌های سایت
- `/network`: نقشهٔ ایران با دایرهٔ پوشش هر استان، فیلتر حوزه و زنجیره، فهرست استان‌ها و زنجیره‌ها
- `/network/<استان>` و `/network/chain/<زنجیره>`
- `/admin/network`: زنجیره‌ها، حوزه‌ها، شعبه‌ها و ورود CSV (اول آزمایشی، بعد «ثبت نهایی»)
- نقشه: Leaflet 1.9.4 با کاشی OpenStreetMap، بدون کلید API. اگر نقشه بار نشود، فهرست‌ها کامل کار می‌کنند.

## مانده
- وارد کردن فهرست واقعی شعبه‌ها پس از قرارداد هر زنجیره (کار تجاری، نه فنی)
- کد رسمی استان‌ها و شهرستان‌ها از منبع رسمی
- «پوشش شبکه برای محل کارکنان» در پنل سازمان (نیاز به ثبت شهر محل کار کارمندان دارد که الان در مدل نیست)
- انتخاب نزدیک‌ترین شعبه در موتور تقسیم سفارش سازمانی (`fulfillment_engine`)
- طراحی صفحهٔ `/network` در فایل فیگمای صفحهٔ اول
