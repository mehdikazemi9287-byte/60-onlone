## روش انتقال (سرور به github.com دسترسی ندارد)
1. بستهٔ `60online-release-20261118-<sha>.tar.gz` (خروجی `git archive` از همین شاخه) + فایل `.sha256`.
2. از مک: بررسی checksum، کپی به سرور، باز کردن در `/opt/60online-rel-20261118`.
3. `deploy/sqlite-upgrade.sh stage <PyPI mirror>`: کد جدید روی **کپی** دیتابیس روی پورت‌های ۸۱۰۰/۳۱۰۰. سایت اصلی دست نمی‌خورد.
4. پیش از switch: برچسب‌زدن ایمیج‌های فعلی (`sixty-backend:prev-20261118`، `sixty-frontend:prev-20261118`) برای برگشت سریع.
5. `deploy/sqlite-upgrade.sh switch`: پشتیبان تازه از دیتابیس، سپس اجرای کد جدید روی دیتابیس اصلی (nginx تغییری نمی‌کند).

## برگشت (rollback)
اسکریپت `rollback` فعلی برای پشتهٔ خیلی قدیمی `/opt/60online` نوشته شده و **برای این انتشار استفاده نشود**. برگشت درست:
```
docker tag sixty-backend:prev-20261118 sixty-backend:latest
docker tag sixty-frontend:prev-20261118 sixty-frontend:latest
docker compose -f /opt/60online-new/deploy/.compose-sixty.yml up -d
```
چون مهاجرت 0082 فقط جدول اضافه می‌کند، کد قبلی روی همان دیتابیس کار می‌کند و نیازی به بازگرداندن دیتابیس نیست (بازگرداندن دیتابیس سفارش‌های بعد از سوئیچ را پاک می‌کند). پشتیبان پیش از سوئیچ در `/root/backups-60online/<زمان>/` است.
