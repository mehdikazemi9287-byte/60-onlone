## تفاوت‌ها با Stitch
- هیرو عکس پس‌زمینه‌ی تبلیغاتی ندارد (عکس واقعی وجود ندارد)؛ به‌جای آن زمینه‌ی سرمه‌ای + عکس واقعی کالای دسته. اسلایدها: اسلاید اول از پنل محتوا (`hero`)، بقیه از بزرگ‌ترین دسته‌های واقعی.
- کارت ونداپی/اقساط و مبالغ آن، تلفن پشتیبانی، آدرس «ارسال به»، امتیاز ستاره، درصد تخفیف، «قیمت پلکانی کارتن»، آمار غرفه‌ها و گردونه‌ی شانس ۶۰کلاب نمایش داده نمی‌شوند (داده‌ی واقعی ندارند).
- رنگ تأکید طبق تصمیم مالک زرد عسلی است (Stitch قهوه‌ای/نارنجی داشت).
- کارت‌های دسته پاستلی با عکس واقعی کالا هستند، نه آیکون.

## شکاف‌های داده/بک‌اند
1. **سبد جدا برای هر حالت وجود ندارد**: جدول `carts` فقط یک سبد فعال برای هر کاربر دارد (`idx_carts_one_active`). پیاده‌سازی نشد و جعل هم نشد؛ هر سه حالت از یک سبد استفاده می‌کنند. نیاز: ستون حالت/کانال در `carts` + قوانین قیمت و پرداخت هر حالت.
2. **شگفت‌انگیز با تایمر**: API تخفیف یا زمان پایان پیشنهاد ندارد ← تایمر و درصد تخفیف حذف شد؛ بخش «پیشنهادهای امروز» فقط کالای موجود با قیمت تأییدشده را نشان می‌دهد.
3. **پرفروش‌ها**: مرتب‌سازی بر اساس فروش در `/storefront/products` نیست ← بخش با عنوان «منتخب» آمده.
4. **قیمت سازمانی روی کارت**: کارت کاتالوگ فقط قیمت خرده‌فروشی دارد؛ پله‌های سازمانی فقط در صفحه‌ی کالا (`offers.tiers.organization`) ← در حالت سازمانی «قیمت پس از استعلام».
5. **۶۰کلاب برای مهمان**: `/loyalty/tiers` احراز هویت می‌خواهد ← مهمان فقط دکمه‌ی ورود می‌بیند؛ عضو موجودی سکه و سطح واقعی را می‌بیند.
6. **نقشه‌ی ۳۱ استان**: فقط شمار فروشگاه و استان از `/stores`؛ نقشه پیاده‌سازی نشد.
7. پیشنهاد دستیار در خود هیرو (کادر جمله) پیاده نشد؛ لینک به `/assistant` است.

## مانده و قدم بعد
1. پیش‌نمایش این شاخه روی سرور پروژه با داده‌ی واقعی و دیدن همه‌ی بخش‌ها با مالک.
2. تأیید صریح مالک برای ادغام و سپس دیپلوی (قاعده‌ی ۱۱).
3. تصمیم درباره‌ی سبدهای جدا برای هر حالت (کار بک‌اند + مهاجرت DB با تأیید).
4. API پیشنهاد زمان‌دار و رتبه‌بندی فروش اگر بخش‌های تایمر/پرفروش لازم است.
