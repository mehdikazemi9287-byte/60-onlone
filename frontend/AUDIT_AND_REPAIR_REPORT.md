# گزارش بررسی، مقایسه، اجرا و اصلاح فرانت‌اند

تاریخ بررسی: ۲۰ مرداد ۱۴۰۵ / 11 August 2026

## نتیجه صریح

این بسته یک رابط کاربری Next.js قابل اجراست، اما در وضعیت تحویلی «فرانت‌اند نهایی متصل به محصول» نبود. صفحات داده‌های نمونه را مستقیم داخل فایل‌ها نگه می‌داشتند و هیچ صفحه‌ای API client موجود را import نمی‌کرد. بنابراین نام خروجی حاضر عمداً `RUNTIME-REPAIRED-CANDIDATE` است و نه `FINAL`.

## آنچه بررسی شد

- ۲۹ فایل source و ۱۱ route برنامه
- build واقعی production با Next.js
- اجرای desktop و mobile در مرورگر headless و ثبت screenshot
- مقایسه endpointهای API با backend فاز ۸
- مقایسه پوشش صفحات با UI قبلی (حدود ۲۵ صفحه)

## اشکالات نسخه ورودی

1. `next.config.ts` با Next 14 سازگار نبود و build را متوقف می‌کرد.
2. Next.js 14.2.5 هشدار امنیتی داشت.
3. آدرس API روی `localhost:5000` بود؛ backend پروژه روی پورت 8000 اجرا می‌شود.
4. update سبد خرید از `PUT` استفاده می‌کرد، ولی backend قبلی `PATCH` می‌خواهد.
5. همه صفحات تجاری از داده‌های mock/static استفاده می‌کردند.
6. تصاویر نمونه از Picsum در محیط واقعی لود نمی‌شدند.
7. ظاهر responsive بود، ولی عمق بصری و هویت سه‌بعدی مورد انتظار را نداشت.
8. بسته جدید فقط ۱۱ route دارد و بخش‌هایی از دامنه قبلی (ادمین، مالی، تأمین‌کننده کامل و گزارش‌ها) در آن وجود ندارد.

## اصلاحات انجام‌شده

- تبدیل config به `next.config.mjs` و ارتقای Next.js به 14.2.35
- اضافه‌کردن reverse proxy هم‌مبدأ برای `/api/v1/*` به `backend:8000`
- اصلاح API client برای deployment و تغییر update سبد به `PATCH`
- حذف وابستگی بصری کارت‌های اصلی به Picsum و افزودن placeholder سه‌بعدی داخلی
- بازطراحی hero با کارت‌های اعتباری سه‌بعدی CSS، glass header، عمق کارت‌ها و پس‌زمینه aurora
- یکپارچه‌کردن نام نمایشی «۶۰ آنلاین» در header، metadata، login، register و footer
- حذف font خارجی برای جلوگیری از شکست منابع در محیط محدود

## شواهد اعتبارسنجی

- `npm run build`: موفق
- TypeScript validation: موفق
- تولید هر ۱۱ route: موفق
- HTTP اجرای home/search/org: 200
- home desktop و mobile: render موفق و responsive

## مواردی که هنوز برای عنوان «Final» لازم است

- جایگزینی داده‌های mock همه صفحات با state/query واقعی API
- پیاده‌سازی auth state، token lifecycle و cart state واقعی
- بازگرداندن routeهای حذف‌شده نسبت به دامنه ۲۵ صفحه‌ای قبلی
- اتصال تصاویر محصول به media واقعی backend
- تست end-to-end با backend و database واقعی و provider پرداخت غیر-mock

این گزارش بخشی از تحویل است تا هیچ ادعای انجام‌نشده‌ای به‌عنوان کار نهایی مطرح نشود.
