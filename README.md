# شصت آنلاین (60online)

مارکت‌پلیس سازمانی و عمده‌فروشی شصت آنلاین، به همراه **وامبی (Vambi)**، موتور جستجو و مقایسهٔ قیمت درون اکوسیستم.
شروع کار سازمانی است (B2B-first) و اکوسیستم بسته است: قیمت‌ها فقط برای اعضای سازمان‌های طرف قرارداد دیده می‌شود و هیچ فیدی به ترب، ایمالز یا باسلام نمی‌رود.

> شاخهٔ کاری: `marketplace-roadmap` — آخرین به‌روزرسانی این فایل: ۱۷ آبان ۱۴۰۵ (2026-11-08)

## کارهای باقی‌مانده (به ترتیب اولویت)

### ۱. راه‌اندازی
- [ ] قرارداد درگاه سپهر، شمارهٔ ترمینال و ثبت آی‌پی سرور
- [ ] یکی کردن کد سرور با مخزن و استقرار (سرور اصلی + سرور آزمایشی جدا)
- [ ] PostgreSQL، دامنه، SSL، پشتیبان روزانه با یک بار تمرین بازگردانی
- [ ] حذف حساب‌های نمونه، cron و پایش سلامت
- [ ] اولین سفارش واقعی پرداخت‌شده

### ۲. حقوقی و مالیاتی (پیش‌نیاز راه‌اندازی)
- [ ] اینماد، ساماندهی، ثبت نام تجاری «شصت آنلاین» و «وامبی»
- [ ] متن نهایی شرایط خرید، شرایط فروشنده و حریم خصوصی از وکیل
- [ ] **مدل نگهداری پول فروشنده‌ها** (تسهیم یا وکالت در وصول). بزرگ‌ترین ریسک است؛ تا تصمیم، تسویه دستی بماند
- [ ] تعیین فروشندهٔ رسمی در خرید اعتباری سازمان‌ها
- [ ] سامانهٔ مؤدیان: SDK و کلید رسمی (کد آماده است)
- [ ] اقساط، خرید دین و پیش‌پرداخت فروشنده تا گرفتن مجوز خاموش بمانند

### ۳. تجاری
- [ ] قرارداد با اولین سازمان‌ها، سقف اعتبار و قیمت قراردادی
- [ ] جذب ۲۰ تا ۳۰ فروشندهٔ اول و دست‌کم ۵۰ کالای قیمت‌دار با عکس
- [ ] قرارداد پست و پیک با تعرفهٔ واقعی
- [ ] قرارداد پذیرندگی اعتبار بیرونی (تارا، دیجی‌پی یا اسنپ‌پی)

### ۴. فنی
- [ ] اتصال خرید دوره‌ای به ثبت سفارش، و اتصال کیف پول رفاهی و اقساط به صفحهٔ پرداخت
- [ ] لغو سفارش سازمانی (آزادسازی موجودی و اعتبار) و تطبیق خودکار سه‌طرفهٔ رسید کالا
- [ ] backfill مشخصات کالاها روی سرور و آزمون صفحه‌ها با دادهٔ واقعی
- [ ] رفع ۴۰۴ صفحهٔ محتوای صفحهٔ اصلی و درست کردن ویترین خالی در `seed.py`
- [ ] امضای رهگیری شرکت‌های حمل
- [ ] اپ بومی روی همان API (PWA ساخته شده است)

## سرور فعلی (60online-prod، آروان)

- **وضعیت ۱۷ آبان ۱۴۰۵:** نسخهٔ قدیمی (۱۰ آبان، بدون اتصال به گیت) در `/opt/60online` با SQLite (`/srv/60online/data/70online.db`) و nginx روشن است. کالا و قیمت تأمین‌کننده‌های واقعی (گلستان، طبیعت، تواضع، آریا) در همین دیتابیس است.
- **بکاپ پیش از ارتقا:** `/root/backup-20261108/` (دیتابیس + کل پوشهٔ کد).
- **ارتقای امن بدون از دست رفتن داده:** [deploy/sqlite-upgrade.sh](deploy/sqlite-upgrade.sh)
  1. `stage`: کد جدید روی **کپی** دیتابیس در پورت‌های ۸۱۰۰/۳۱۰۰ آزمایش می‌شود؛ سایت فعلی دست نمی‌خورد.
  2. `switch`: بکاپ تازه، توقف نسخهٔ قدیم، اجرای کد جدید روی دیتابیس اصلی (nginx تغییری نمی‌کند). فقط با تأیید مدیر.
  3. `rollback`: برگشت به دیتابیس و نسخهٔ پیش از سوئیچ.
- مهاجرت به PostgreSQL و Caddy طبق `docs/DEPLOY.md` بعداً و جدا انجام می‌شود.

## اجرا

- **محلی:** بک‌اند در `backend/` (وابستگی‌ها در `requirements.txt`) و فرانت در `frontend/` با `npm run dev`

- **بررسی پیش از راه‌اندازی:** `scripts/launch_preflight.py` (فقط‌خواندنی)
